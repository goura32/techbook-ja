# 第1章 なぜRustか

## Rustが注目される理由

本章では、なぜRustがこれほどまでに注目されたのかを理解します。

### Rustの急成長と実績

#### TIOBE指数での急上昇

TIOBEインデックスはプログラミング言語の人気度を示す指標です。Rustは**過去最高位**を記録し、その後も着実に順位を上げたままの推移を示しています。

この急成長は以下のような事実を物語ります：
- Rustがニッチな言語から**主要言語の仲間入りをした**
- C/C++の代替言語として実質的に採用されている
- コンパイル時の強制力が、大規模プロジェクトにおいて信頼性を大きく向上させている

#### Stack Overflow調査での「最も憧れの言語」3年連続

Stack OverflowのAnnual Developer Surveyでは、2023年以降「もっとも働きたいと思う言語」としてRustが連続で1位を獲得しています。開発者のRustへの高い関数を示しています。

### Linuxカーネルへの採用

最も象徴的な出来事の一つが、**LinuxカーネルへのRust公式採用**です。Linuxカーネルは、1991年以来C言語一辺倒で書かれてきましたが、Linus Torvalds自身が「Rustはカーネル開発者にとって良い選択だ」と明言し、公式にRustのサポートが追加されました。

これはRustの安全性・信頼性が「システムプログラミングの最高峰」と言えるカーネル開発に耐えうるとの判断を示しています。

### 主要プロジェクトでの本格採用

| プロジェクト | 採用範囲 | 目的 |
|---|------|---|
| Firefox | ブラウザエンジン、ネットワーク層 | セキュリティ改善、パフォーマンス向上 |

## C/C++との比較

### C/C++の課題

C/C++は歴史上最も広く使われているシステムプログラミング言語ですが、いくつかの根本的な課題があります。

| 課題 | 例 | リスク |
|---|----|------|
| メリメリ | ポインタの使い過ぎ | バッファオーバーランによる脆弱性 |
| 未定義動作 | NULLポインタ参照 | 予期せぬ動作 |
| 手動メモリ管理 | malloc/freeのミスマッチ | メリメリリーク |
| 競合状態 | 複数スレッド同時アクセス | データ競合 |
| 型システム | 静的なチェック不足 | コンパイル時に発覚しない誤り |

これらの問題はC/C++のセキュリティ脆弱性の大半を占めています。

### Rustの解決策

Rustはコンパイル時にこれら全ての課題を解決します。

```rust
// Cでの問題例（上記コードは例示であり、未検証です）
#include <stdlib.h>

// Cでは、以下のような問題がコンパイルエラーにならない
char *buf = malloc(10);  // mallocした領域の解放を忘れる可能性
buf[100] = 'a';          // バッファオーバーランがコンパイル時に検出されない
// free(buf);            // freeを忘れる可能性

// Rustでは同様の問題はコンパイル時に検出される
fn main() {
    // let mut buf = [0u8; 10];
    // buf[100] = b'a';      // コンパイルエラー！
    
    let s1 = String::from("hello");
    let s2 = s1;  // s1はs2に「所有権が移動」。s1はもう使えない
    // println!("{}", s1);  // コンパイルエラー！使用済みの変数
}
```

## Rustの特性まとめ

### 「生産性」と「安全性」と「性能」の3つの柱

Rustは以下の3つを同時に実現しようとする言語です。

1. **安全性**
   - メリメリリークなし
   - データ競合なし
   - バッファオーバーランなし
   - 使用後解放（use-after-free）なし

2. **性能**
   - C/C++と同等の処理速度
   - ゼロコスト抽象化（ゼロコスト抽象化）
   - コンパイル時チェックによる実行時のオーバーヘッドなし

3. **生産性**
   - cargoによるビルド・パッケージ管理
   - excellentドキュメント
   - richなエコシステム（crates.ioに40万以上のライブラリ

### zero-cost abstraction（ゼロコスト抽象化）

Rustのゼロコスト抽象化とは、「高水準の抽象機能を使っても、C/C++と同じ性能が得られる」という概念です。

```rust
// Rustのイテレータはコンパイル時に最適化される
// Cでforループを回すコードと同等の機械語が生成される

fn sum(v: &[i32]) -> i32 {
    v.iter().sum()  // このコードは、Cのforループと同等の性能
}

fn main() {
    let data = vec![1, 2, 3, 4, 5];
    println!("{}", sum(&data));  // 15
}
```

## なぜ今、Rustなのか

Rustを学ぶ理由：

1. **エコシステムが成熟期に入った**
   - crates.ioには40万以上のパッケージ
   - 主要なミドルウェアがRustで書かれつつある
   - 組込みからサーバーサイドまで、あらゆる領域で利用可能

2. **企業での採用が本格化**
   - Linuxカーネル、Windows、Chrome、Firefoxなど主要プロジェクトでの採用
   - AWS、Google、Microsoftなどのクラウド大手での採用

3. **将来性が確認されている**
   - Rust Foundationの設立（Linux Foundation配下）
   - ガバナンスポリシー、ステディな進化

## まとめ

本章で学んだこと：

- RustがTIOBE、Stack Overflow調査で高い評価を得ている
- Linuxカーネルに公式採用され、主要プロジェクトで本格採用
- C/C++が抱えるセキュリティ問題（バッファオーバーラン、メリメリリークなど
- Rustは安全性・性能・生産性を同時に実現する言語
- 「ゼロコスト抽象化」で、高レベルなコードがC/C++同等の性能に
